# Task Hub — плагин для DSH: задачи, календарь и почта в левой панели

> **Статус:** M0 в репозитории (запись в навигации + пустая панель); списки, календарь и почта — по плану ниже.
> **Репозиторий:** <https://github.com/akkrevsky/dsh-task-hub> · установка: `dsh plugin --profile web add github:akkrevsky/dsh-task-hub`.
> **Цель:** один плагин `dsh-task-hub`, который добавляет в левую навигацию DSH две записи —
> **«Задачи»** (списки · дерево · календарь) и **«Почта»** (единый ящик Gmail / Яндекс / Mail.ru),
> с двусторонней синхронизацией календарей и превращением письма в задачу.
> **Макеты:** [`docs/mockups/`](docs/mockups/) — архитектура и четыре экрана; интерактивная галерея — `docs/mockups/index.html`.

| Что | Как |

| Агент | Инструменты `tasks_create / tasks_update / tasks_list / calendar_agenda / mail_to_task`, работающие по тем же правилам, что панель |

**Вывод:**

1. **Готового плагина «дерево + календарь + 3 провайдера + почта» нет.** Есть три хороших куска (календарь, почта, todo-хранилище), но они живут в разных плагинах, с разными хранилищами и без связи «задача ↔ событие».
2. **Механика левой панели проверена по живой установке**: слот `sidebar.panellist` (иконки навигации) + keyed-слот `main` (центральная панель, ключ = id записи) + `ctx.layout.selectPanel(id)`. Это не «встраивание в чужой DOM», а штатная точка расширения.
3. **Писать своё имеет смысл**, но не с нуля: берём проверенные решения (CalDAV-обмен, JSON-store с lock, IMAP-пресеты), не форкаем чужие плагины — у них другие лицензии, модели данных и они не дают общей панели.
4. **Промежуточный вариант** (если нужно «здесь и сейчас»): поставить `dsh-calendar` + `dsh-email` и жить с двумя панелями и без дерева. Это не закрывает ТЗ, поэтому идём своим плагином.

## 3. Пользовательские сценарии

1. **Утро.** «Задачи» → «Сегодня»: задачи из всех списков, рядом события из трёх календарей; просроченное сверху.
2. **Планирование.** Создать задачу в дереве, задать срок 18:00 → появляется в календаре и уходит в Google Tasks / VTODO.
3. **Перенос.** Перетащить задачу в календаре на другой день → меняется срок, событие в провайдере обновляется.
4. **Почта.** Переключиться на «Почта» → письмо Анны → «В задачу»: создаётся задача со ссылкой на тред и сроком.
5. **Внешняя правка.** Событие перенесли в Яндекс.Календаре → в DSH приезжает при следующей синхронизации (и наоборот).
6. **Агент.** «Поставь задачу на ревью PR #431 до пятницы» → tool → карточка в панели (с подтверждением, как в `dsh-global-todo`).
7. **Настройки.** Добавить аккаунт, «Проверить связь», увидеть статус «нужен пароль» и отозвать токен.

## 4. Архитектура

Схема: [`docs/mockups/00-architecture.svg`](docs/mockups/00-architecture.svg) (PNG рядом).

### 4.1 Client-половина (браузер)

React-компоненты, зарегистрированные в штатных слотах. Ни одного `document.body`, ни одного чтения чужого DOM.

| Слот | Зачем |
|---|---|
| `sidebar.panellist` (list) | Две иконки навигации: «Задачи» и «Почта» (id = `tasks-hub`, `tasks-hub-mail`) |
| `main` keyed, ключи `tasks-hub` / `tasks-hub-mail` | Две центральные панели |
| `sidebar.toggle.badge` | Бейдж «сегодня 5» на свёрнутом рейле |
| `sidebar.panellist.actions` | Строка «Синхронизировать всё» в меню «Ещё» |
| `settings.section` + `settings.section.icon` | Страница «Tasks Hub»: аккаунты, проверка связи, OAuth-вход |
| `settings.general.item` | Тумблер «показывать бейдж» |
| `conversation.composer.dock` (опционально, M6) | Компактная строка «Сегодня · 3 задачи» под полем ввода |
| `tool.call.toolview` (опционально) | Карточка задачи прямо в чате после вызова инструмента |

Состояние: серверные данные — из Remote-методов (не хранить в слотах), UI-состояние (активный вид, свёрнутые узлы, выбранный день) — в собственном store + `localStorage` для запоминания вида.

### 4.2 Host-половина (процесс DSH)

Один сервис `ctx.tasksHub`:

- `TasksStore` — дерево, списки, статусы, повторения, порядок;
- `SyncEngine` — планировщик синхронизации по аккаунтам (очередь, backoff, circuit breaker при auth-ошибке);
- `MailService` — IMAP-соединения, заголовки, тела по требованию;
- `AgentTools` — те же операции для модели.

Клиент общается только через Remote-методы сервиса (`tasks.list`, `tasks.mutate`, `calendar.range`, `calendar.sync`, `mail.list`, `mail.read`, `accounts.status`, стрим `sync.progress`). Никаких прямых обращений к файлам из браузера.

**Таймеры:** только в host-половине; синхронизация раз в 5 минут (настраивается в Config), плюс ручной запуск из меню.

### 4.3 Хранение и секреты

```
~/.dsh/plugin-data/dsh-task-hub/
├── tasks.json           # задачи, списки, связи (tmp + rename, flock)
├── calendar-cache.json  # события, etag/syncToken, окно −30/+180 дней
├── mail-index.json      # заголовки писем, курсоры папок
└── sync.log             # последние 200 записей (без тел писем)
```

- Пароли приложений и OAuth-токены — **только** `ctx.credentials`; в `settings.yaml` и JSON-файлах их нет.
- Настройки плагина (интервал, окно календаря, бейдж) — `Config` в `cordis.patch.yml`, чтобы переживали обновления.
- Импорт/экспорт: JSON и Markdown (как в `dsh-global-todo`), ICS-импорт для календаря.

### 4.4 Инструменты агента

| Инструмент | Назначение |
|---|---|
| `tasks_create` | Задача: список, родитель, срок, приоритет, теги |
| `tasks_update` | Изменить статус/срок/приоритет; `done` требует подтверждения человеком |
| `tasks_list` | Выборка по списку/сроку/статусу |
| `calendar_agenda` | События и задачи на диапазон, с учётом таймзоны |
| `mail_to_task` | Создать задачу из письма со ссылкой на тред |

Правила те же, что у панели — один сервис, два входа (как в `dsh-better-sidebar`/`dsh-context`).

## 5. Модель данных

```ts
type Task = {
  id: string                  // ulid
  listId: string
  parentId?: string           // дерево
  title: string
  notes?: string
  status: 'open' | 'done' | 'cancelled'
  priority: 0 | 1 | 2 | 3     // low..urgent
  dueAt?: string              // ISO + tz
  startAt?: string
  allDay?: boolean
  rrule?: string              // RFC 5545
  tags: string[]
  order: number
  refs?: ProviderRef[]        // { accountId, kind: 'caldav'|'google'|'local', uid?, href?, etag? }
  createdAt: string
  updatedAt: string
  completedAt?: string
}

type Account = {
  id: string
  provider: 'google' | 'yandex' | 'mailru'
  capabilities: ('calendar' | 'tasks' | 'mail')[]
  displayName: string
  username: string
  credentialKey: string       // ссылка в ctx.credentials, не сам секрет
  calendarIds: string[]
  status: 'ok' | 'needs-password' | 'error'
  lastSyncAt?: string
}
```

Событие в кэше: `uid`, `etag`, `summary`, `start/end + tz`, `allDay`, `rrule`, `location`, `description`, источники.
Связь «задача ↔ событие» — отдельная запись `Link { taskId, accountId, uid }`, чтобы перенос задачи не пересоздавал событие.

**Конфликты:** LWW по `updatedAt` + сверка `etag`/`syncToken`; если обе стороны изменились — задача попадает в список «Конфликты», ничего не теряется.

## 6. Провайдеры: конкретика

| | Google | Яндекс | Mail.ru |
|---|---|---|---|
| Календарь | Calendar API v3, `events.list` + `syncToken` | CalDAV `https://caldav.yandex.ru` | CalDAV `https://calendar.mail.ru/principals/mail.ru/<id>/` |
| Задачи | Tasks API (`tasklists`, `tasks`) | VTODO в CalDAV | VTODO в CalDAV (проверить на живом аккаунте) |
| Почта | `imap.gmail.com:993` (OAuth2 XOAUTH2 или пароль приложения) | `imap.yandex.ru:993` | `imap.mail.ru:993` |
| Вход | OAuth 2.0, loopback + PKCE, свой client_id | пароль приложения «Календарь» / «Почта» | «Пароль для внешних приложений» (тип CalDAV) |
| Особенности | refresh-токен в режиме Testing живёт 7 дней — нужно опубликовать приложение | пароль активируется до 2–3 часов | точный href principal копируется из настроек календаря |

**Алгоритм синхронизации**

1. Первичная: окно −30/+180 дней, полная выгрузка, сохранение `etag`/`syncToken`.
2. Далее: CalDAV — `PROPFIND` по ctag + `calendar-multiget` изменённых; Google — `events.list` с `syncToken` (410 → полная пересинхронизация).
3. Локальные изменения — очередь исходящих операций; при ошибке 429/5xx — экспоненциальный backoff с джиттером (макс. 5 мин), при 401 — статус «нужен пароль» и остановка очереди.
4. Почта — polling INBOX раз в 60–120 с, только заголовки (`BODY.PEEK[HEADER.FIELDS …]`), тело по клику.
5. Вся сеть — на host; браузер не ходит к провайдерам напрямую (CORS и токены).

**Зависимости (host):** `ical.js` (RRULE/VEVENT/VTODO), `imapflow` + `mailparser` (почта), остальное — встроенный `fetch` и самописный CalDAV-клиент (~300 строк: discovery, PROPFIND, REPORT). Google SDK не нужен.

## 7. UI/UX (что на макетах)

- **Шапка панели:** заголовок + сегмент вида «Списки | Дерево | Календарь» + индикатор синхронизации + чипы аккаунтов (G/Y/M).
- **Списки:** умные списки (Входящие, Сегодня, Скоро, Когда-нибудь, Выполнено) + пользовательские списки с цветами; строки: чекбокс, заголовок, срок, приоритет, провайдер, тег; подзадачи с отступом.
- **Дерево:** вложенность с гайдами, прогресс `2/3`, правая карточка задачи: описание, подзадачи, связи (событие календаря, сессия DSH), кнопки «Открыть в календаре» / «Выполнить».
- **Календарь:** месяц (время + название в чипе, цвет провайдера), переключатель «Месяц / Неделя / Повестка», правая колонка: мини-месяц, статусы подключений, «Дальше».
- **Почта:** ящики и папки, список, чтение; «В задачу» создаёт задачу со сроком письма и ссылкой на тред; блок «Связанная задача».
- **Общие правила:** только токены `--dsw-alias-*`, светлая/тёмная тема наследуется, i18n ru/en, полная клавиатурная навигация, пустые состояния и ошибки, `role`/`aria` на тумблерах и меню.

## 9. Риски и ограничения

| Риск | Влияние | Что делаем |
|---|---|---|
| Google OAuth в режиме Testing: refresh-токен живёт 7 дней | Синхронизация отваливается раз в неделю | Инструкция «опубликовать приложение», статус ошибки в настройках |
| Пароль приложения Яндекса активируется не сразу | «Проверить связь» падает сразу после выдачи | Явное сообщение и повтор через 10 минут |
| Особенности CalDAV Mail.ru (principal href) | Не находится календарь | Discovery + ручное поле href + кнопка «Проверить» |
| RRULE, таймзоны, переход на летнее время | Дубли и съезд событий | `ical.js`, тесты на переходах, хранение tz явно |
| Большой ящик | Долгий первый sync | Только заголовки, лимит 200 на страницу, пагинация |
| Апгрейд DSH меняет слоты | Панель может не отрисоваться | Проверка на 0.2.2-rc.2 при каждом апгрейде; `inject` для необязательных сервисов |
| Сеть в контейнере | Нет исходящих к провайдерам | Проверить `curl` к `caldav.yandex.ru` / `oauth2.googleapis.com` на этой установке |
